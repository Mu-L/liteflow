# Rule-DB ZooKeeper Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a ZooKeeper-backed Rule-DB provider and unified Publisher using metadata-only startup, lazy content reads, CuratorCache events, and Curator transactions.

**Architecture:** Store metadata and content in separate znode trees and watch only metadata. Buffer CuratorCache events before manifest initialization, activate from observed `mzxid`, then perform an immediate second reconciliation because a multi-znode ZK manifest is not an atomic snapshot.

**Tech Stack:** Java, Maven, Apache Curator framework/recipes 5.3.0, curator-test, Jackson, ServiceLoader, JUnit 5.

---

**Prerequisite:** Complete `2026-07-13-rule-db-core-publisher-sql-redis.md`. Keep traditional `liteflow-rule-plugin/liteflow-rule-zk` unchanged.

- [ ] **Step 3: Implement two CuratorCache listeners**

Create one cache for chain metadata root and one for script metadata root. NODE_CREATED/NODE_CHANGED decode the new metadata and emit UPSERT with `data.getStat().getMzxid()`. NODE_DELETED uses oldData path, business version, and `oldData.getStat().getMzxid()` to emit DELETE.

Before activation, store events in an ordered buffer keyed by `mzxid` plus target identity so multiple changes in one transaction are retained. Activation drops entries at or below baseline, replays the remainder, enters UP, and requests an immediate reconcile. Close both caches, guard callbacks with `running`, and make repeated close harmless.
